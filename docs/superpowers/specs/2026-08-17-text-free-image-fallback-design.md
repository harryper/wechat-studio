# 无字配图与 MiniMax 质量重试设计

## 目标

消除公众号 AI 配图中的伪文字。图片服务成功返回但画面包含标题、标签、段落或乱码时，不再直接视为合格图片；不新增 OpenAI API 费用，以 MiniMax 的严格提示词和同供应商重试为主。

## 方案选择

采用“严格无字 Prompt + 可插拔质量检查 + MiniMax 同供应商重试”。不直接调用 Codex 会话内置生图工具，因为它不是项目后端可部署 API；现有 OpenAI provider 保持兼容，但不作为本次方案的运行依赖。

暂不实现封面程序叠字：当前产品要求是无字配图，先解决伪文字。未来需要标题时，再以 Pillow/SVG/Canvas 和项目内置中文字体做确定性叠字。

## Prompt 设计

- 不把完整文章标题作为需要表现的字符串，也不使用书名号包裹概念。
- 将主题和关键点描述为视觉语义，而非排版内容。
- 每张图统一追加中英双语硬约束：纯视觉插画；不得出现标题、段落、字母、汉字、数字、标签、图例、水印、Logo、书页、屏幕界面或标牌。
- 避免“信息图、流程图、时间线、学术海报、数据图表”等天然诱导文字的构图词。
- 封面保留干净留白，但明确留白中也不得生成文字。

## 供应商与质量流程

`toolkit/image_gen.py` 的生成流程从“一次成功即接受”扩展为“异常或质量拒绝均可重试”：

1. 当前供应商生成候选图片。
2. 调用可选的候选验证器。
3. 验证器拒绝时记录原因，以强化后的无字 Prompt 重试 MiniMax。
4. 达到配置的重试次数后，才尝试配置中已有的其他供应商；所有候选失败或被拒绝时，沿用现有 PIL 占位图降级。

使用本地 Tesseract 做轻量文字检测，不调用云 OCR，也不产生 API 费用。Docker 镜像安装英文识别包；伪文字通常表现为拉丁字符，达到可信字符阈值即拒绝候选并重试。非 Docker 环境没有 Tesseract 时跳过检测、记录 `not_available`，严格 Prompt 仍然生效，且不会误报已完成 OCR 检查。

默认不要求 OpenAI API 额度，也不改变当前供应商顺序。Codex 会话生图只用于人工补图，不进入 Web 后台自动链路。

## 状态与可观测性

- 保留现有 `real`、`mixed`、`placeholder` 聚合结果，避免破坏 Web API。
- `image-status.json` 中单图状态继续兼容现有值；新增独立的质量/供应商诊断文件，记录使用的 provider、拒绝原因和是否执行文字检查。
- 不记录 API Key 或完整敏感响应。

## 测试

- Prompt 测试：不再包含书名号标题；包含中英双语无字约束和禁用对象。
- 重试测试：首个 MiniMax 候选被验证器拒绝后会使用强化 Prompt 重试；合格候选立即返回；达到上限后才进入现有供应商降级链；全部拒绝时抛出明确错误。
- Web 回归测试：五张图生成与占位图降级行为保持兼容。
- 运行完整 pytest 套件。

## 非目标

- 不在本次引入云 OCR 账号或额外付费服务。
- 不用 Codex CLI/会话工具充当生产图片服务。
- 不重生历史工作目录中的图片；代码上线后可通过现有“重生全部图片/指定图片”操作更新。
