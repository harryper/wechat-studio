# 无字配图与 OpenAI 质量兜底设计

## 目标

消除公众号 AI 配图中的伪文字。图片服务成功返回但画面包含标题、标签、段落或乱码时，不再直接视为合格图片；OpenAI GPT Image 2 作为可部署的质量兜底供应商。

## 方案选择

采用“严格无字 Prompt + 可插拔质量检查 + 按供应商重试”。不直接调用 Codex 会话内置生图工具，因为它不是项目后端可部署 API；项目继续使用正式 OpenAI Images API 的 `gpt-image-2`。

暂不实现封面程序叠字：当前产品要求是无字配图，先解决伪文字。未来需要标题时，再以 Pillow/SVG/Canvas 和项目内置中文字体做确定性叠字。

## Prompt 设计

- 不把完整文章标题作为需要表现的字符串，也不使用书名号包裹概念。
- 将主题和关键点描述为视觉语义，而非排版内容。
- 每张图统一追加中英双语硬约束：纯视觉插画；不得出现标题、段落、字母、汉字、数字、标签、图例、水印、Logo、书页、屏幕界面或标牌。
- 避免“信息图、流程图、时间线、学术海报、数据图表”等天然诱导文字的构图词。
- 封面保留干净留白，但明确留白中也不得生成文字。

## 供应商与质量流程

`toolkit/image_gen.py` 的供应商链从“异常才切换”扩展为“异常或质量拒绝都切换”：

1. 当前供应商生成候选图片。
2. 调用可选的候选验证器。
3. 验证器拒绝时记录原因并尝试链中下一供应商。
4. 全部供应商失败或被拒绝时，沿用现有 PIL 占位图降级。

第一阶段不引入体积较大的 OCR 依赖。验证器接口与失败原因先进入通用生图链；Web 流程使用轻量启发式或可配置 OCR 命令。若运行环境没有 OCR，严格 Prompt 仍生效，且不会误报已完成 OCR 检查。

OpenAI provider 使用正式 `v1/images/generations`。配置中 MiniMax 可继续排第一；当候选被质量检查拒绝时，GPT Image 2 自动接手。

## 状态与可观测性

- 保留现有 `real`、`mixed`、`placeholder` 聚合结果，避免破坏 Web API。
- `image-status.json` 中单图状态继续兼容现有值；新增独立的质量/供应商诊断文件，记录使用的 provider、拒绝原因和是否执行文字检查。
- 不记录 API Key 或完整敏感响应。

## 测试

- Prompt 测试：不再包含书名号标题；包含中英双语无字约束和禁用对象。
- 供应商链测试：首个候选被验证器拒绝后会尝试 OpenAI 候选；合格候选立即返回；全部拒绝时抛出明确错误。
- Web 回归测试：五张图生成与占位图降级行为保持兼容。
- 运行完整 pytest 套件。

## 非目标

- 不在本次引入云 OCR 账号或额外付费服务。
- 不用 Codex CLI/会话工具充当生产图片服务。
- 不重生历史工作目录中的图片；代码上线后可通过现有“重生全部图片/指定图片”操作更新。
