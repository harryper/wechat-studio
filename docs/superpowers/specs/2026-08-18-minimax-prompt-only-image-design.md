# MiniMax 纯提示词配图优化设计

## 目标

通过优化 MiniMax 提示词降低配图中的伪文字概率，同时恢复正常的五图交付体验。图片质量由用户在工作台人工判断，不再使用 OCR 自动拒绝候选。

## 产品原则

- MiniMax API 成功返回图片即保留为真实图片。
- 只有 API 没有返回图片时才使用 PIL 占位图。
- 用户发现乱码或构图不满意时，使用现有“重生指定图片”功能再次生成。
- OpenAI provider 继续默认关闭，不产生 OpenAI API 费用。
- 不自动重生历史图片。

## Prompt 策略

### 总体风格

从“学术插画、编辑插画、概念图、机制图、线稿说明图”切换为“电影感场景插画或写实视觉隐喻”。每张图片只表达一个场景、一个视觉中心和一个具体动作。

所有图片共用以下约束：

- 文章标题和关键点只作为语义参考，不得以字符形式出现在画面中。
- 不出现标题、段落、字母、汉字、数字、水印或 Logo。
- 不出现箭头、路线、流程节点、标签、图例、表格或图表。
- 不出现书页、文件、标牌、屏幕、设备界面或海报布局。
- 不使用需要文字才能成立的说明性构图。
- 横版构图，单一视觉焦点，背景保持自然且简洁。

### 五张图片的场景分工

1. 封面：一个具有冲突感的核心视觉隐喻；通过天空、墙面、雾气或暗部形成自然留白，不描述“标题区域”或“文字区域”。
2. inline-1：历史或起源场景，一个人物正在完成具体动作；场景内不出现文献、书页和标牌。
3. inline-2：用两至三个真实物体表达机制或关系；不使用箭头、节点、网络和流程结构。
4. inline-3：实验、观察或证据场景，人物与实体器材互动；不出现记录纸、仪表读数和显示屏。
5. inline-4：现实生活中的应用或边界场景；不出现手机、电脑和可见界面。

五张图复用封面的色调和质感描述，避免同一篇文章风格跳变。

## 生成流程

`webapp/render.py` 继续为五个角色分别构建提示词，并调用 `generate_image`。Web 调用不再传入 OCR validator、质量重试次数或 OCR diagnostics。

`toolkit/image_gen.py` 恢复简单的 provider fallback：

1. 调用当前启用的 provider。
2. API 成功则写入图片并返回。
3. API 异常则尝试下一个已启用 provider。
4. 所有 provider 都失败时，由 Web 层写入占位图。

不再保留候选排序、文字阈值或自动质量拒绝逻辑。

## 删除项

- 从 Dockerfile 删除 `tesseract-ocr` 和 `tesseract-ocr-eng`。
- 删除 `detect_text`、OCR 阈值、Tesseract 子进程和文字检测测试。
- 删除 Web 层的 validator、每供应商质量重试和 `image-diagnostics.json` 写入逻辑。
- 删除与 OCR、自动文字检测和候选拒绝相关的说明。

历史工作目录中已经存在的 `image-diagnostics.json` 无需迁移或删除；新任务不再创建和更新该文件。

## 保留项

- provider 的 `enabled` 配置与 OpenAI 默认关闭逻辑。
- `image-status.json` 的 `real`、`mixed`、`placeholder` 状态。
- 全部图片和指定图片的重生入口。
- 图片压缩、尺寸处理和 provider 异常 fallback。
- `dist/openclaw` 与源码同步。

## 测试与验收

- Prompt 测试验证五张图均使用具体场景、单一焦点和对应的角色约束。
- Prompt 测试禁止出现“学术插画、编辑插画、概念图、流程图、信息图、标题区域、文字区域”等诱导词。
- Web 测试验证生图调用不再传 validator 和质量重试参数。
- provider 开关测试继续验证 OpenAI 默认关闭。
- API 成功的五张图片全部记为 `real`；只有真实异常才降级为占位图。
- Docker 镜像构建后不包含 Tesseract。
- 运行完整 pytest 和 `git diff --check`。

## 已知限制

MiniMax 仍可能忽略无字约束。该方案不承诺自动识别或消除所有伪文字，而是通过更适合模型的场景构图降低概率，并由用户通过预览和单图重生完成最终质量控制。
